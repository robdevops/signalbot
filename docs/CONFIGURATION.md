# Configuration

Every setting, read from the environment (`/etc/signalbot.env` in the install). Only `MODEL_API_KEY` is needed to get started (with `SIGNAL_DM_USERS` to let more than group admins DM the bot on Signal), and `SIGNALCLI_SOCKET` if signal-cli doesn't listen on `127.0.0.1:7583`; see the [README](../README.md#configuration).

| Variable | Default | Description |
|---|---|---|
| `SIGNALCLI_SOCKET` | `127.0.0.1:7583` | signal-cli's `host:port` (`daemon --tcp`), or its Unix socket path (`daemon --socket`), such as `/run/signal-cli/socket`; see [Unix socket](SOCKET.md). Set it, even to the default, to run on Signal and Telegram at once |
| `SIGNAL_DM_USERS` | `admins, mods` | Who may DM the bot on Signal: unset, `admins, mods`: only an admin or moderator of a group the bot is in with them (see [Who may use the bot](#who-may-use-the-bot)); `all`: anyone; `none`: no one; or any of `admins`, `mods` and IDs, separated by commas or whitespace; an ID is a UUID or a number, with or without `signal:`. The startup log warns if no one may |
| `SIGNAL_GROUP_IDS` | `all` | The Signal groups the bot answers in: unset or `all` (anywhere in the list), any group anyone adds it to; `none`, no group; or the groups' IDs, as signal-cli's `listGroups` gives them (`signalctl call listGroups`), separated by commas, semicolons or whitespace; anything after `#` is ignored. From a group not listed the bot neither answers nor keeps anything (messages, chatter, reactions, member changes, edits, deletes), and logs the group's ID once a run; its admins don't count as admins for `SIGNAL_DM_USERS`, `/schedule` doesn't offer it, and a scheduled post to it is dropped. Once connected, at each start, the bot logs the groups it is in, by name and ID, marking any this setting doesn't list (and warning then), so a group someone else added it to shows. While it is `all`, it also warns and suggests the line that lists the groups it is in, with their names. Recommended: set it |
| `TELEGRAM_BOT_TOKEN` | empty | The bot's token from Telegram's BotFather. Set, the bot answers on Telegram instead of Signal; with `SIGNALCLI_SOCKET` set too, on both at once. Never logged; see [Telegram](../README.md#telegram) |
| `TELEGRAM_API_URL` | `https://api.telegram.org` | The Bot API's base URL, for a self-hosted [Bot API server](https://github.com/tdlib/telegram-bot-api) |
| `TELEGRAM_DM_USERS` | `admins, mods` | Who may DM the bot on Telegram: unset, `admins, mods`: only an admin or moderator of a group the bot is in with them (see [Who may use the bot](#who-may-use-the-bot)); `all`: anyone; `none`: no one; or any of `admins`, `mods` and IDs, separated by commas or whitespace; an ID is a user's numeric ID, with or without `telegram:` |
| `DISCORD_BOT_TOKEN` | empty | The bot's token from Discord's developer portal (your application, Bot, Reset Token). Set, the bot answers on Discord instead of Signal; with another network's setting too, on each at once. Never logged; see [Discord](../README.md#discord) |
| `DISCORD_API_URL` | `https://discord.com/api/v10` | Discord's REST API base URL; the gateway's address comes from it. Only tests change it |
| `DISCORD_DM_USERS` | `admins, mods` | Who may DM the bot on Discord: unset, `admins, mods`: only an admin or moderator of a group the bot is in with them (see [Who may use the bot](#who-may-use-the-bot)); `all`: anyone; `none`: no one; or any of `admins`, `mods` and IDs, separated by commas or whitespace; an ID is a user's ID, with or without `discord:` |
| `SLACK_BOT_TOKEN` | empty | The Slack app's Bot User OAuth Token, `xoxb-…`. Set, the bot answers on Slack, alongside any other network whose setting is set. Never logged; see [Slack](../README.md#slack) |
| `SLACK_APP_TOKEN` | empty | The Slack app's app-level token, `xapp-…`, with `connections:write`, for Socket Mode; required with `SLACK_BOT_TOKEN`, and a missing one stops the bot at start. Never logged |
| `SLACK_API_URL` | `https://slack.com/api` | Slack's Web API base URL |
| `SLACK_DM_USERS` | `admins, mods` | Who may DM the bot on Slack: unset, `admins, mods`: only an admin or moderator of a group the bot is in with them (see [Who may use the bot](#who-may-use-the-bot)); `all`: anyone; `none`: no one; or any of `admins`, `mods` and IDs, separated by commas or whitespace; an ID is a member ID (`U…`), with or without `slack:` |
| `MODEL` | `deepseek/deepseek-v4.1-flash-1017` | The model's name at the API: on OpenRouter as `provider/model` |
| `MODEL_API_KEY` | empty | API key for the model's API, such as your [OpenRouter](https://openrouter.ai) key; none is sent when empty. With neither this nor `MODEL_API_URL` the bot has [no model](MODELS.md#no-model) |
| `MODEL_API_URL` | `https://openrouter.ai/api/v1` | Base URL of an OpenAI-compatible chat completions API; see [Language models](MODELS.md#other-providers) |
| `MODEL_REASONING` | `low` | Reasoning effort, e.g. `low`, `medium`, `high` (`none` to omit). Sent as OpenRouter's `reasoning.effort`, or elsewhere as `reasoning_effort` |
| `MODEL_SEARCH` | `true` | Lets the model search the web (OpenRouter's web search tool) when it decides to, citing the sites it uses by url; searches are billed. Only on OpenRouter: on another API it is left out, with a warning. Accepts `true`/`false`, `yes`/`no`, `on`/`off`, `1`/`0` |
| `MODEL_SYSTEM_PROMPT` | empty | Extra instructions, appended to the built-in prompt (which keeps answers short and Signal-sized and, when the model has tools, asks it to name its source) |
| `CHARTS` | `true` | The built-in line and pie charts. Set to `no` if you don't want charts, or wish to use your own charts MCP server ([MCP connectors](FILES_LINKS_TOOLS_MCP.md#mcp-connectors)); `go build -tags nocharts` leaves them out of the binary too |
| `IMAGE_MODEL` | `openai/gpt-image-2` | The OpenRouter image model the bot makes pictures with when asked for a drawing, art, a diagram or the like; `off` turns pictures off. Only on OpenRouter; each picture's cost counts toward `DAILY_BUDGET`. See [Images](FILES_LINKS_TOOLS_MCP.md#images) |
| `IMAGE_QUALITY` | `medium` | `low`, `medium`, `high` or `auto`: higher costs more; the log shows what each picture cost |
| `DAILY_BUDGET` | `1` | US dollars each group and each DM may spend on the model a day, midnight to midnight in `TZ`; `0` for no cap. Once a chat reaches it, the bot says once "I've reached today's spending limit for this chat, so I'll answer again in 5 hours. Commands that don't need me to think still work." and until midnight reacts ⏳ to anything else there, answering only commands that don't use the model. Today's spending is saved in `budget.json` in `STATE_DIRECTORY`, so a restart doesn't reset it. An [addon](FILES_LINKS_TOOLS_MCP.md#addons) allowed the model has its requests charged to the chat it names, and refused once that chat is over. Only OpenRouter reports costs, so with another API it isn't applied |
| `DARKMODE` | `off` | Chart colours: `off` for light charts (also `false`, `no`, `0`, `light`), `on` for dark (also `true`, `yes`, `1`, `dark`), or the hours charts are dark in `TZ`, such as `18:00-6:00`, `18-6` or `6pm-6am` |
| `FILES` | `true` | Show the model the files people send ([Files](FILES_LINKS_TOOLS_MCP.md#files)): PDFs, audio, text and Office documents. Off (`false`, `off`, `0`), files are never fetched, and the model is told only that a file was attached, so it can say it can't read it |
| `GROUP_ADMINS` | `admins, mods` | Who may change a group's [alerts](FEEDS.md) (`/alerts` with anything after it, and the menu's toggles): unset, `admins, mods`: that group's admins and moderators; `all`: anyone in the group; `none`: no one; or any of `admins`, `mods` and IDs, the networks' together, as for `SCHEDULE_ALLOWED_USERS`. Anyone may see a group's alerts and open the menu. A DM's alerts are its owner's to change |
| `GROUP_CONTEXT` | `true` | Remember group messages not addressed to the bot as context, so "what do you think @bot" works without replying to the message; they are never logged |
| `HISTORY_MAX` | `10` | Most messages remembered per chat, the bot's replies and, in groups, messages not addressed to it included. When full, the older half is dropped, so the start of the model's request stays the same for several messages and comes from the API's prompt cache (cheaper and faster); below 3, the oldest message is dropped |
| `INTRO` | built-in sentence | Overrides the self-introduction; `{name}`, `{model}` (without any OpenRouter `provider/` prefix) and `{tools}` (the names of the tools, or `none`) are substituted |
| `MAX_CONCURRENCY` | `32` | Conversations in flight at once; messages beyond this are dropped, with a warning |
| `MCP_CONFIG` | empty | Path of an MCP servers file; see [MCP connectors](FILES_LINKS_TOOLS_MCP.md#mcp-connectors) |
| `<SERVER>_…` | none | An [addon's](FILES_LINKS_TOOLS_MCP.md#addons) own settings, read by the addon, not the bot. An addon server gets every variable that starts with its name in capitals, anything but letters and digits as `_`, then `_` (the server `geo` gets `GEO_STATE_DIR` and the rest; `GEO_STATE_DIR`, if not set, is `addons/geo` in `STATE_DIRECTORY`, which the addon creates), plus `PATH`, `HOME` and, if set, `TZ`, `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `SSL_CERT_FILE` and `SSL_CERT_DIR`, and nothing else, so none of the other settings above reach it. A server whose prefix one of the settings above starts with (such as `model` or `mcp`) is a config error. Each addon documents its own, such as [GeoGuess's](https://github.com/robdevops/GeoGuess#settings) |
| `STATE_DIRECTORY` | working directory | Where features save their state, one file each, such as `/schedule`'s `schedules.json`, `mcp.json` when an MCP server is an [addon](FILES_LINKS_TOOLS_MCP.md#addons), `mcp-posts.json` for [direct commands](FILES_LINKS_TOOLS_MCP.md#direct-commands)' buttons on Telegram, `mcp-feeds.json` for [feeds](FEEDS.md) (and the core its `budget.json`, and `keyboards.json` once `/keyboard` sets a Telegram DM's keyboard; on Telegram the bot also keeps `telegram-groups.json`, the groups it knows it is in, for the startup log, and warns if it can't write it); the bot won't start if a feature that saves can't list and write it. Set by systemd's `StateDirectory=signalbot` (`/var/lib/private/signalbot`) and by the Docker image (`/data`, which must be writable by user 65532) |
| `SCHEDULE_ALLOWED_USERS` | `admins, mods` | Who may [schedule](SCHEDULING.md) posts in a group: unset, `admins, mods`: that group's admins and moderators; `all`: anyone who shares the group with the bot; `none`: no one; or any of `admins`, `mods` and IDs, the networks' together (a Signal UUID or number, a Telegram numeric ID, a Discord ID, a Slack member ID `U…`, each with or without `signal:`, `telegram:`, `discord:` or `slack:`). Anyone allowed to DM the bot may schedule posts in their own DM. Checked again at each run: a run its user may no longer post is skipped, and the schedule kept |
| `TOOL_LINGER_ROUNDS` | `2` | Replies a keyword-gated tool group (charts, an MCP server with `keywords`) stays offered after the last one that matched its keywords or used its tools; `0` offers it only on a matching message. Any use or match starts the count again, so a run of follow-ups keeps it. Capped at `HISTORY_MAX`. See [How tools are offered](FILES_LINKS_TOOLS_MCP.md#how-tools-are-offered) |
| `TZ` | `UTC` in Docker, the host's under systemd | Time zone for `/schedule` times without an offset and for `DARKMODE` hours, e.g. `Australia/Sydney`; addons get it too, for the times they write (GeoGuess's round deadline) |

A number that can't be read is warned about at startup, and the default used. `OPENROUTER_API_KEY` is now `MODEL_API_KEY`, and `REASONING` and `SYSTEM_PROMPT` are now `MODEL_REASONING` and `MODEL_SYSTEM_PROMPT`, and `SIGNAL_DM_USER_IDS` and `TELEGRAM_DM_USER_IDS` are now `SIGNAL_DM_USERS` and `TELEGRAM_DM_USERS`; the old names are ignored, with a warning at startup. `LOG_LEVEL` is gone: every level is always written (see [Logs](../TECHNICAL.md#logs)).

The default `INTRO` is short paragraphs: `hi, I'm *{name}*, your open source assistant running {model}.`, `I respond to @{name} and replies to my messages.`, `Tools:` then `{tools}`, one tool category per paragraph, then `{more}`, lines features add (such as `Type "/schedule" for schedules and reminders.`, only in a DM, where schedules are made), then the link `https://github.com/robdevops/signalbot/blob/main/README.md` (Signal makes a bare url clickable; it has no named links).

The cost logged with each reply is the amount OpenRouter reports billing for it. An API that reports no cost gets none logged.

## Who may use the bot

In groups the bot answers anyone, in any group it is in; on Signal only in the groups `SIGNAL_GROUP_IDS` lists, if set. At each start the bot logs the Signal groups it is in, by name and ID, with a warning if any isn't listed (`journalctl -u signalbot | grep 'Signal: groups ('`), so a group a stranger added it to shows. Who may DM it is each network's `<NETWORK>_DM_USERS`, who may schedule posts in a group is `SCHEDULE_ALLOWED_USERS`, and who may change a group's [alerts](FEEDS.md) is `GROUP_ADMINS`. Each is `admins, mods` when unset, or `all`, `none`, or any of `admins`, `mods` and IDs (`admins, 123`). `all` opens the bot to anyone who can reach it: on Discord, anyone in a server with it; on Slack, anyone in the workspace; on Signal and Telegram, anyone at all. Each DM is its own chat with its own `DAILY_BUDGET`.

An ID may carry its network's prefix or not: `signal:` and `telegram:` are optional, and a Discord ID (17 digits or more) or a Slack member ID (`U…` or `W…`) is read as one with `discord:` or `slack:` or without. So `SCHEDULE_ALLOWED_USERS` and `GROUP_ADMINS` can list every network's people together, as the log writes them.

Admins and mods are, on each network:

| Network | Admins | Mods |
|---|---|---|
| Signal | a group's admins, of a group in `SIGNAL_GROUP_IDS` | none: Signal groups have only admins |
| Telegram | a group's owner and administrators | none: Telegram calls everyone with powers an administrator |
| Discord | a server's owner, and anyone whose roles give Administrator or Manage Server | anyone whose roles give Manage Channels, Manage Messages, Moderate Members, Kick Members or Ban Members |
| Slack | the workspace's owners and admins | none: Slack doesn't tell a bot who manages a channel |

For a DM, someone counts if they are one in any group the bot is in with them: on Discord, by their roles in a server (not a channel's overrides); on Telegram, only in a group the bot has seen since it started, as the Bot API can't list a bot's groups. For `/schedule` they must be one in the group the post is for, and for `GROUP_ADMINS` in the group whose alerts they change (in a forum topic, its group): on Discord, by their permissions in that channel. The network is asked only when the setting names a role and doesn't list them. Whether someone is one is asked of the network when it matters, and the answer kept in memory for 10 minutes. Someone who may no longer DM the bot isn't answered there, nor sent [feeds'](FEEDS.md) alerts or other posts in their DM, and their schedules' runs are skipped, but kept, while they may not; `/schedule list` marks a group schedule its user may no longer post.

On Discord, once connected, the bot logs the servers it is in, by name and ID, and warns when it is added to another, so you can see one someone else added it to; Public Bot off in the developer portal stops that (see [Discord](../README.md#discord)).

On Telegram, anyone can add the bot to a group while BotFather's Allow Groups is on (the default), and whoever makes a group is its owner, an admin: so by default they may DM the bot, and schedule posts in their group. Once the bot is in your groups, send BotFather `/setjoingroups`, choose the bot, and Disable; switch it on briefly to add the bot to another group yourself. While it is on, the bot warns so at startup.

To see where the bot is, read the startup log: on Telegram, after it connects, it lists the groups it knows it is in, each by title and ID (`Telegram: groups the bot knows of (2): …`), and warns as it learns of a new one (`Telegram: the bot is in a new group: …`), so a group someone else added it to shows up. As the Bot API can't list a bot's groups, the list is the bot's own, kept in `telegram-groups.json` in `STATE_DIRECTORY` from when it is added to a group or sees anything there.

On Slack, people from another organisation can talk to the bot in a channel shared with it (Slack Connect). At every startup the bot warns with the name and ID of each such channel it is in (with none, it notes how many channels it is in); remove it from any you don't expect.
